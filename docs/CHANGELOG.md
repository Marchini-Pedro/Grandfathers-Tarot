## 2.0.0 - after the first in-game test of the custom mods
The user tested: health, size, run speed and hit mass worked; melee attack speed, gunner fire rate and shots per burst did not. Offline only again.
- **The three attack stats are put back by a hook, not by a timer.** The user's guess (a mission-wide Havoc modifier takes priority) matches the source: the minion buff extension recomputes its stats every frame while a buff that touches them is on the unit, and each recompute drops the written factor (`buff_extension_base.lua:318-354`, `minion_buff_extension.lua:97-101`); the 4 times a second check could only restore it in between, so an attack almost always read the plain value. `Tuning.install` now hooks `BuffExtensionBase._update_stat_buffs_and_keywords` (post) and puts the factor on top right after each recompute (retired on unload like the bypass hooks); the timer stays as a fallback. If they still do nothing in game the next suspects are the values being too small to notice (105 percent) and the attack actions not reading the stat for that enemy.
- **Two new custom mods**: *Explosion damage taken* and *Damage over time taken* (burning, toxin and bleeding), 0-300 percent, 100 = normal, 0 = none: the game's `damage_taken_from_explosions` / `_burning` / `_toxin` / `_bleeding` stats, which the damage calculation adds to the target's damage modifiers (`damage_calculation.lua:532-555`). Recipe names `explosion`, `dot` (aliases blast, burn, burning, toxin, damage over time). The Custom screen has nine rows now.
- **The countdown under or above the cards is centred**: the label ("Card revealed in") and the time are placed as one line centred on the fuse (widths estimated from the letters), they were two halves around the middle and the wide label pulled the pair to the left.
- **The info column of an enemy row no longer overlaps the steppers**: it is 340 wide (it ends where the repeat stepper starts) and holds 66 characters in two lines: the modifiers (cut at 40 as before, colours kept), a bar, the custom mods in what is left, with "..." when cut.
- **The pointer on a segment of the Deck's strip** lights that card's tile, shows its name over the strip and raises the segment (one quiet hotspot per segment, placed in `_paint_strip`).

## 2.0.0 - Custom mods per enemy group (health, size, run speed, melee attack speed, gunner fire rate, shots per burst, hit mass)
- **A "Custom" button beside "Mods"** on every enemy row of a card's own screen opens the group's **custom mods**: seven values in percent of what the game normally gives that enemy (100 = unchanged), each with - and +, a click on the number (or the row's name) for a number box, and Reset while it is not 100. The row of the card's screen lists them after the modifiers ("Enraged  |  Health 150%, Size 130%"), and the card's modifier line on its tile and in the HUD banner says "Custom".
- **Ranges and steps**: health 10-1000 (10), size 25-300 (5), run speed 25-300 (5), melee attack speed 25-400 (5), gunner fire rate 25-400 (5), shots per burst 25-500 (25), hit mass 10-1000 (10). In the text editor and in shared cards they are written after the modifiers in braces: `3 crushers[enraged]{health=150 size=130}@2` (names have aliases: hp, run speed, fire rate, shots per burst, hit mass...; values are clamped; an unknown name is refused with the list). Groups with different custom mods stay separate; the enemy picker never adds to a group that has them.
- **How the game gets them** (`spawn/tuning.lua`, host only, right after the unit spawned; no new breed or buff, every value is one the game already reads): health = the spawn parameter `optional_health_modifier`; run speed = a movement modifier of the unit's navigation (synced by the game); hit mass = `set_hit_mass` like the Enraged buff (synced by the game); melee attack speed, gunner fire rate and shots per burst = the unit's own stats `melee_attack_speed`, `ranged_attack_speed`, `minion_num_shots_modifier`, which the attack actions read when an attack starts; the buff system rewrites a stat when a buff that touches it changes, so the value is checked 4 times a second and put back on top; size = `Unit.set_local_scale` on the root node (what the game's Rampaging buff does), and because nothing in the game syncs it, the host sends `[network id, percent]` to the other players (new RPC `rw_scale`, also to players who join late) and their copy of the mod applies it when the unit exists there.
- **Limits, from the source**: a player without the mod sees the normal size; only the model grows, the areas that can be hit may not (not verifiable offline); shots per burst and fire rate work for the rifle/gunner shooting (`MinionAttack.start_shooting`), not for snipers, the plasma gunner (their own shot counts) or shotgun blasts; a later Final Toll (Red) trigger sets the hit mass from the breed again; size changes the model, not the unit's collision with the level.
- `/rw_status` shows how many units carry custom attack stats and how many sizes were sent / are waiting.
- This is the brief's optional step 6 (per-group health and size multipliers), extended to the seven values the user asked for. The brief wanted a one-crusher test in the game first; that test has NOT happened: everything here is **offline only** (logic +35, editor +21 checks).

## 2.0.0 - Deck polish and twelve faces (the user's requests after playing the Deck)
The user played the Deck in game and asked for the following; everything below is **offline only** (tests and the preview PNG), none of it has been seen in the game yet.
- **Rarity and the ten pips are relative to the cards in the draw.** Ten pips = the card with the heaviest weight in the draw (the likeliest), one pip = the lightest (the least likely), the rest in proportion (`Cards.level(weight, lo, hi)`: `1 + round(9 * (w - lo) / (hi - lo))`); when every card weighs the same all of them have ten pips; a weight of 0 has none. **Rare** (the pus-yellow outline, "rare" in the label, the HUD's outline too) is now "among the two lowest levels of a draw whose weights differ", no longer "weight 2 or less". The director computes the same range over the whole pool (cooling cards count) and syncs the flag (`r`), so the HUD of a client agrees with the Deck. A card never shows a percentage.
- **Click the pips to set a card's chance** (hover shows what a click would set and names the level over the strip: "The Procession: chance 7 of 10"). The weight written is the one that shows that level among the *other* cards (`Cards.weight_for_level`: the closest whole number in the others' lightest-to-heaviest range, so pip 10 = the heaviest other card's weight, pip 1 = the lightest's; a lone card has nothing to compare with, the pip is the weight 1-10; others that all weigh the same: pip 10 matches them, a lower pip is that fraction, which makes the card the lightest, one pip). Works on a card that is out of the draw too (it stays out). The ten pip hotspots sit side by side from the tile's left edge to its right edge (no dead strip), are quiet on hover (no sound ticks), and never overlap the face or the state line.

## 2.0.0 - step 4b: cooldown looks on the tiles
- **A card that has been drawn rests on its tile, in the look of its card** (the look is the card's `cl_` setting; the default is "rot" and, for every Murmur card, "whisper"; Rain of Rot has "vial"). The clock and "Back in" come from the director's played-time cooldown clock (a client's synced map), so the tiles follow the real cooldown, also on a client.
  - **Rot and renewal**: everything that has the suit's colour (the suit label and mark, the glow, the weight pips, the frame) goes grey rgb(74,74,64), then brown rgb(90,70,49) at 35 percent, ochre rgb(194,122,44) at 70 percent, and back to the suit's colour at the end; the text (name, composition, whisper) is 50 percent faint and comes back to full.
  - **The murmur returns**: the whisper writes itself letter by letter (never cutting a multi-byte letter), the quote closes when it is whole, and the whole card is 60 percent faint until it is back.
  - **The vial fills**: a pus-yellow liquid rises from the bottom of the tile with a bright top line and three bubbles (hidden while there is very little liquid).
  - **Ready ping** (option "Ping when a card is back", on by default, in the group "The Spread (your screen)"): when a resting card is back, a ring leaves the tile and fades over 1.1 s, the name flashes from the suit colour back to the text colour, and the state line says "Ready" for that moment; no ping for a card that finished while the editor was closed.

## 1.4.2
Out-of-memory crash investigation (log `console-2026-09-29-04.44.24-85a45457-*.log`, details in doc 06). The log does not prove RealmsWaves caused it, but three things in the mod were risky and are now hardened:
- **Lua memory guard (new option "Memory guard", default 800 MB, 300-1000):** the game's Lua heap is a fixed 1 GB (`Not enough memory reserved for heap 'lua_heap', reserved: 1073741824`). When the heap is above the guard the mod stops spawning (units stay queued), refuses NEW waves with a message, and logs one warning; before pausing it forces one full garbage collection (at most every 15 s), since a high reading is often uncollected garbage. Spawning resumes by itself when memory drops. `/rw_status` now prints the Lua heap, the guard and whether spawning is paused.
- **Failed position searches are throttled:** when no hidden point was found near the players, the full occlusion query (up to ~27 nav groups and hundreds of points, each allocating) reran on every feed tick (every 0.15 s) for as long as the wave waited. A failed search is now remembered for 1.5 s (about 10 times fewer queries).
- **Reload hygiene:** DMF hooks cannot be removed, so every hot reload (Ctrl+Shift+R) left the old instance's hooks active in the chain, each still counting/subtracting. `mod.on_unload` now retires the old instance: its hooks become pass-throughs, its tracked-unit set and job queues are released.

## 1.3.0

In the editor each enemy row has a second stepper ("Added each repeat"); the initial count may go to 0 while a group repeats; the wave has "Repeat every" and "Repeat for" steppers, and "Spread radius".
