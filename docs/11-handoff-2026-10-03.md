## Working rules and gotchas (from CLAUDE.md and the journal)

- Feature branches from an up-to-date `main`; small, separate commits; commit messages through `git commit -F <file>` (no BOM); keep the
  docs current in the same session; every .md under 100 KB; extensive tests including multiplayer edge cases (a client without the mod, an older
  host, a unit that vanishes, nil targets, hot reload).
- Lua files are tab-indented. Make multi-line edits with a small script file (Python, `miss` list, `newline=""`), not by retyping tabs.
- The logic harness sits at Lua's limit of 200 locals per chunk: new test state goes into one table, not new `local`s.
  An `error("x")` caught by `pcall` carries `file:line:` in front of the text: match the two halves separately.
- Never chain `git stash` with other commands. (The author's machine has an old `stash@{0}` from `feature/workshop-redesign`: local only, its
  content is already in `main`; ignore it.)
- Never edit the Vortex-managed `TwitchVersus` / `RealmsEvent` mods; game source reference: `Content/Darktide-Source-Code` (the editor harness no
  longer needs it).
- Console logs of the last game run: `%APPDATA%\Fatshark\MicrosoftStore\Darktide\console_logs` (newest file).
- Install for a game test: the repository contents go in `Content/mods/RealmsWaves/`, `RealmsWaves` on its own line in
  `Content/mods/mod_load_order.txt` after `Realms`; disable TwitchVersus and RealmsEvent while testing.
